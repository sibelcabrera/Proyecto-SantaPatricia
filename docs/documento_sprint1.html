1. Qué es y qué hace el sistema

Es una aplicación web para controlar el catálogo de insumos y productos de Santa Patricia. En este Sprint 1 permite:

FunciónQué hace
Iniciar sesión (HU01)Cada trabajador entra con su correo y contraseña. Según su rol (Administrador, Encargado de Producción, Cajero o Almacenero) puede hacer más o menos cosas.
SeguridadSi alguien se equivoca de contraseña 5 veces seguidas, la cuenta se bloquea 15 minutos. Sin iniciar sesión no se puede ver nada.
Ver el inventarioTabla con todos los productos: código, nombre, área, stock, precio, vencimiento y estado (Óptimo, Bajo o Crítico). Tarjetas con el resumen.
Buscar y filtrarBuscador por nombre o código (encuentra «azúcar» aunque se escriba sin tilde) y botones para ver solo un área (Cocina, Panadería, Pastelería, Cafetería, Minimarket).
Registrar productos (HU02)Solo el Administrador. Formulario con nombre, área, unidad, stock, stock mínimo, precio y vencimiento. El código se genera solo (Azúcar → AZU-001). El sistema calcula el stock si llega en sacos o cajas.
Eliminar productosSolo el Administrador. El producto deja de aparecer, pero no se borra de la base (se guarda el historial).
¿Cómo se abre? En NetBeans se abre la carpeta backend y se pulsa Run. Se abre solo el navegador en el login: http://localhost:8087/santapatricia/. No hace falta usar la terminal.

2. Estructura y arquitectura

Sigue el esquema del documento del curso (puntos 1, 2 y 3): React → API REST con JSON → Java con Servlets → MySQL.

FRONTEND · React (carpeta frontend/) — pantallas: login, inventario, formulario. Hecho por el equipo de front.
▼  petición HTTP con JSON (GET, POST, PUT, DELETE) + token
SERVLET (servlet/) — recibe la petición y responde. No tiene reglas de negocio.
▼
SERVICE / SERVICEIMPL (service/) — reglas del negocio: validar datos, generar el código, bloquear tras 5 intentos.
▼
DAO / DAOIMPL (dao/) — el único lugar donde hay SQL. Usa JDBC.
▼
MySQL · santapatricia_db (database/) — tablas, relaciones y claves.

4. Cómo leer la pantalla del inventario

¿Qué significa «45 / mín. 20 L»?

45 / mín. 20 L

45 = stock actual: hay 45 litros de ese producto ahora en el almacén.
mín. 20 = stock mínimo: lo que siempre debería haber; si baja de 20, hay que comprar.
L = la unidad de medida del producto (litros).

Ejemplo real de la base: Aceite vegetal → 45 / mín. 20 L: hay 45 litros y el mínimo es 20, está bien abastecido.

El estado del stock (semáforo)

EstadoReglaEjemplo (mínimo = 20)
ÓptimoEl stock es mayor que el mínimoHay 45 → 45 > 20 → Óptimo
Stock bajoEl stock es igual o menor que el mínimoHay 15 → 15 ≤ 20 → Bajo: conviene comprar pronto
CríticoEl stock es la mitad del mínimo o menosHay 8 → 8 ≤ 10 (mitad de 20) → Crítico: comprar ya

Las otras columnas

ColumnaQué muestra
SKUEl código automático del producto (ej. ACE-001).
Precio«S/ 9.90 / L» = cada litro cuesta 9.90 soles.
VencimientoFecha en día/mes/año. «—» = no vence.
Tarjetas de arribaTotal de productos, cuántos están Óptimos, en Stock bajo y Críticos. Siempre suman el total.
Botones de área«Pastelería (14)» = hay 14 productos de pastelería; al pulsarlo solo se ven esos.
Buscador (arriba)Busca por nombre o código mientras escribes.
PapeleraEliminar. Solo la ve el Administrador.

5. Formulario «Nuevo producto» y «¿Cómo llega?»

Solo el Administrador ve el botón Nuevo producto. Los campos con * son obligatorios.

CampoQué se escribe
Nombre *Qué producto es. Ej.: «Azúcar rubia». Debajo aparece el código que se asignará (AZU-005).
Área *Cocina, Panadería, Pastelería, Cafetería o Minimarket.
Unidad de medida *En qué se va a contar el stock: KG, G, L, ML, UND (unidad) o PAQ (paquete).
¿Cómo llega? (opcional)Calculadora para cuando la mercadería llega en envases (ver abajo).
Stock que entra *La cantidad total que entra, en la unidad elegida. Se llena sola si usas «¿Cómo llega?».
Stock mínimo *Debajo de esta cantidad el producto se marca como Bajo o Crítico.
Precio (S/) *Precio por unidad de medida: por KG, por L, por UND… (no por saco).
VencimientoFecha de vencimiento. Vacío = no vence.

«¿Cómo llega?» explicado

[ cantidad de envases ] sacos / cajas / paquetes de [ contenido de cada envase ] [unidad] = stock que entra

Primer número = cuántos envases llegaron (sacos, cajas, jabas, paquetes…).
Segundo número = cuánto trae cada envase, medido en la unidad elegida.
El sistema los multiplica y llena «Stock que entra».

Llega a la panadería…Unidad elegidaSe escribeStock que entra
10 sacos de azúcar de 10 kgKG10 sacos de 10100 KG
5 sacos de harina de 50 kgKG5 sacos de 50250 KG
3 jabas de huevos de 30UND3 jabas de 3090 UND
2 cajas de leche con 12 litrosL2 cajas de 1224 L
4 cajas de 500 g de polvo de hornearG4 cajas de 5002000 G
Importante «¿Cómo llega?» solo es una calculadora: en la base se guarda únicamente el total (100 KG), no los sacos. Si la mercadería no llega en envases, se deja vacío y se escribe directo el stock que entra. El precio siempre es por la unidad (por KG), no por el saco.

Qué pasa al pulsar Guardar

  1. React envía los datos al backend (POST /api/inventario/productos) con el token del usuario.
  2. El backend revisa que el usuario sea Administrador; si no, responde «Su rol no tiene permiso».
  3. Revisa cada campo: vacíos, negativos, unidad o área inexistente. Si algo falla, el mensaje aparece debajo de cada casilla.
  4. Revisa que el nombre no exista ya («Ya existe un producto llamado…»).
  5. Genera el código (AZU-005), guarda en MySQL y devuelve el producto.
  6. La pantalla muestra un aviso verde y el producto resaltado en verde en la lista.

8. La regla del profesor: nada se toca a mano en la base

La regla es que las entradas, salidas y cualquier dato no se escriban directamente en MySQL, sino siempre a través del sistema. Este proyecto la cumple así:

Cómo se cumpleExplicación
✓Todo dato nuevo entra por la pantallaEl usuario registra productos en el formulario; nadie necesita abrir Workbench para agregar o cambiar datos.
✓Un solo camino hacia la baseReact → Servlet → Service → DAO → MySQL. El único código que escribe SQL es el DAO; las pantallas nunca tocan la base.
✓Reglas antes de guardarEl Service valida cada dato (vacíos, negativos, repetidos) antes de que llegue a MySQL. Un dato mal escrito no se guarda.
✓Solo quien tiene permisoSolo el Administrador registra o elimina, y el backend lo verifica con el token en cada petición.
✓Nada se borraEliminar = desactivar (activo = 0). La información queda para el historial y las auditorías.
✓Los scripts SQL son solo para instalaresquema.sql y datos_prueba.sql se usan una vez, para crear la base y cargar los datos iniciales. Después todo se hace desde el sistema.
✓Consultas protegidasSe usa PreparedStatement con «?»: lo que escribe el usuario nunca se mezcla con el SQL (evita la inyección SQL).
A tener en cuenta para el Sprint 2 En el Sprint 1 el stock se escribe al registrar el producto. Las entradas por compra (HU03) y las salidas por venta o producción (HU04, HU05) aún no existen. Cuando se hagan, el stock debe cambiar solo con movimientos registrados (con fecha, usuario y motivo, para el kárdex). Hoy la API permite editar un producto, incluido su stock (PUT, solo Administrador, sin pantalla todavía). Conviene que en el Sprint 2 la edición ya no cambie el stock y que este solo se mueva con entradas y salidas.

12. Pendientes y observaciones

«Error» en la carpeta assets

Qué es: NetBeans marca en rojo los archivos de backend/src/main/webapp/app/assets (index-….js y index-….css).

Por qué pasa: esos archivos no se escriben a mano: los genera npm run build con todo el código de React comprimido en una sola línea, y con reglas modernas de CSS (Tailwind 4: @property, @layer) que el revisor de NetBeans no conoce. NetBeans los revisa como si fueran código normal y los marca.

¿Hace algo malo? No. En el navegador esos archivos cargan correctamente (sin errores en la consola) y el sistema funciona.

Cómo se corregirá (más adelante): que NetBeans ignore esa carpeta (es código generado) o servir el front compilado desde fuera de src. No se tocó, como se pidió.

13. Preguntas frecuentes

PreguntaRespuesta
¿Qué significa «45 / mín. 20 L»?Hay 45 litros (stock actual) y lo mínimo que debería haber son 20 litros. Ver sección 4.
¿Qué pongo en «¿Cómo llega?»?Primer número: cuántos envases (sacos, cajas, jabas). Segundo: cuánto trae cada uno en la unidad elegida. El sistema multiplica. Es opcional.
¿Por qué no escribo el código del producto?Lo genera el sistema con las 3 primeras letras del nombre + un número, para que siempre sea ordenado y nunca se repita.
¿Por qué el cajero no ve «Nuevo producto»?Por HU01: solo el Administrador registra o elimina. Los demás roles consultan.
¿Por qué al eliminar no se borra de la base?Para conservar el historial; en los próximos sprints las entradas, salidas y el kárdex harán referencia a esos productos.
¿El precio es por saco o por kilo?Por la unidad de medida (por kilo si la unidad es KG).
¿Por qué el estado no se guarda?Se calcula al momento comparando stock y mínimo; así nunca queda desactualizado.
¿Qué es el token (JWT)?Un «pase» firmado que el backend entrega al iniciar sesión. React lo envía en cada petición; el backend sabe así quién es y qué rol tiene. Si alguien lo modifica, se rechaza.
¿Puedo volver a los datos iniciales?Sí: ejecutar otra vez esquema.sql y datos_prueba.sql. Ojo: borra lo registrado.
¿Qué pasa si escribo mal la contraseña 5 veces?La cuenta se bloquea 15 minutos. Es una medida de seguridad contra quien intenta adivinar contraseñas.
